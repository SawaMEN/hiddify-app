# VetrOFFProxy в VetrOFF Client

VetrOFF Client распознаёт канонические ссылки `vetroff://` с версией
профиля `v: 1`. Ссылки импортируются как нативный outbound `vetroff` в
модифицированном sing-box (через Go SDK VetroffProxy), а не как обычный
HTTP/SOCKS-прокси.

## Импорт

Сгенерируйте ссылку при помощи `vetroff share` из той же совместимой
версии VetroffProxy и добавьте её в VetrOFF Client через буфер обмена,
QR-код, «Поделиться» или открытие ссылки в Android. Данные авторизации
передаются напрямую в SDK; само приложение не выводит их в качестве имени
профиля. Импортированная ссылка остаётся конфиденциальным материалом:
не пересылайте её в публичные журналы или отчёты.

Также поддерживаются текстовые подписки с отдельными строками
`vetroff://`. Сложные цепочки прокси с VetroffProxy запрещены:
у этого транспорта пока нет поддержки внешнего detour.

## Транспорт

- TCP через HTTP/2, HTTP/3, WebSocket и XHTTP (зависит от профиля и
  возможностей сервера).
- UDP через v2-ассоциации SDK для небондированных профилей. На стороне
  VetroffProxy сервер должен разрешать UDP.
- Несколько серверов, стратегии балансировки и Bond — в том числе
  тайм-ауты из конфигурации.
- Проверка TLS-сертификатов и SPKI pinning выполняется SDK. Отключения
  проверки TLS через share link нет.

VetroffProxy выполняется *внутри* Android-ядра Go. Приложение должно
исключать собственные сетевые сокеты из TUN через настройки VpnService,
иначе возможно зацикливание трафика.

## Важные ограничения

Это интеграция **на уровне исходников**, которая начнёт работать в
установленном APK только после сборки и выпуска Android ARM64 AAR из
`SawaMEN/hiddify-core` с соответствующим
`SawaMEN/hiddify-sing-box`, а затем обновления VetrOFF Client до
сборки с этим AAR.

Нативные Linux-движки Necko/NSS/Neqo не включены в эту Android-интеграцию;
используется доступный Go-движок SDK. Для подтверждения совместимости
необходимы Android-сборка и тестовое подключение к серверу VetroffProxy.
