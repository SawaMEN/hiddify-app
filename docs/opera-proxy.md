# Opera Proxy in the Android client

The native Free catalog has one **Opera Proxy** entry. Its short Russian/English notice appears before catalog import and before choosing a saved Opera profile, in both the profile sheet and full profile screen. Cancel leaves the active profile unchanged. The notice is rendered as an introduction and four spaced, labeled bullet points: TCP limitations, availability, privacy and credential updates. Europe, Asia and Americas endpoints are collected into one profile. The existing server list offers manual selection, latency tests, delay sorting and automatic server selection; these are region choices, not guaranteed individual countries.

## API transport compatibility

The previous client used ordinary HTTPS with SNI and system certificate verification for `api2.sec-tunnel.com`. Upstream [routerich/opera-proxy](https://github.com/routerich/opera-proxy) uses **no SNI and a self-signed API endpoint**. Sending SNI can reach the wrong virtual host (HTML / HTTP 405), while rejecting the bootstrap certificate prevents registration entirely.

`NativeOperaApiTransport` matches that upstream bootstrap transport using an isolated HTTP/1.1 client. A connected-IP socket factory and disabled OkHttp TLS extensions prevent inferred or Android-added SNI. Its certificate trust exception and hostname verifier apply only to the fixed `api2.sec-tunnel.com` API; redirects and other request hosts are forbidden. Only generated anonymous subscriber/device identifiers and public Opera client identifiers are sent. The API peer is **not authenticated by a trusted certificate**, as in upstream: this bootstrap step is not a claim of end-to-end authenticated TLS. No user subscription headers, personal accounts or configuration data are sent to it.

Bootstrap DNS uses separate, normally verified DoH clients (Cloudflare / Google), then public system DNS addresses. Subscription requests, DoH, and all actual Opera proxy connections keep certificate verification. Proxy outbounds now also suppress SNI using `tls.disable_sni`, while `tls.server_name` continues to verify the expected region hostname. The upstream MIT notice is in `licenses/opera-proxy-MIT.txt`.

Registration, device access and discovery errors have a sanitized stage and numeric HTTP/API code, in the user's language. Timeouts/DNS/TLS failures are distinguished. Raw response text, tokens and request headers are not logged. The overall bootstrap has a 30-second deadline, and imports remain cancelable. Region discovery is retried once after a transient failure. Each region receives a share of the remaining deadline, so one stalled region cannot consume the other regions’ request budget. Regions whose discovery still fails are omitted on imports and updates. Available regions are saved normally; unavailable regions are not copied from old profiles or invented. Import fails only when registration fails or no region supplies valid endpoints. The certificate names `eu0.sec-tunnel.com`, `as0.sec-tunnel.com` and `am0.sec-tunnel.com` are not DNS endpoint addresses: live checks found all three unresolvable. They are used only to verify certificates. HTTPS port 443 is preferred when an API endpoint advertises multiple ports.

## Updates and compatibility

`builtin:opera` is the new local source ID. Legacy `builtin:opera-EU`, `builtin:opera-AS` and `builtin:opera-AM` profiles remain updateable and now generate all regions as well, without deleting profiles or user data. The remote Free catalog cannot create built-in sources or change API URLs. Updates preserve profile identity and user overrides; renewal runs before service startup and defaults to hourly profile updates. Long-running sessions with the Activity closed may require reconnecting when credentials expire. A failed registration aborts startup rather than choosing a direct fallback.

Normal core DNS and routing settings apply. HTTP proxy outbounds reject UDP routed to them; existing direct exclusions remain effective. Temporary credentials are stored in private profile files and appear in raw configuration exports: do not publish them.

## Verification

Deterministic JVM tests cover the real no-SNI/self-signed TLS handshake, Digest challenge retry, session cookies, source confinement, DoH parsing, all-region generation, regional retries, partial availability with one or two regions omitted, rejected fictional DNS aliases, sanitized localized failures and cancellation. `./android/gradlew -p tool/kotlin-tests operaSmoke` explicitly checks the live service: it generates a profile with production code, verifies proxy and destination certificates, and checks every advertised server with real HTTPS (`www.gstatic.com/generate_204`) and HTTP (`captive.apple.com/hotspot-detect.html`) requests without printing or uploading credentials. The opt-in `Opera Proxy smoke check` workflow runs this separately from ordinary unit tests. A runner check does not guarantee reachability through every ISP or validate an Android device's TUN/DNS behavior.
