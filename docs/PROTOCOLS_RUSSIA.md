# Протоколы и ограничения в РФ

Проверено 6 октября 2026. Инвентаризация относится к ядру, закреплённому
в этом форке, и тегам `hiddify-core/Makefile`, а не ко всем названиям в sing-box.
«Не найдено подтверждений» означает недостаток публичных измерений, а не
незаметность. Ни один протокол не гарантирует доступ при блокировке IP,
SNI, UDP или при разрешительном списке сети.

## Что подтверждено

- [FOCI 2026: QUIC SNI censorship](https://www.petsymposium.org/foci/2026/foci-2026-0010.php):
  измерения марта–апреля 2026 в трёх российских городах подтверждают фильтрацию
  QUIC v1 по SNI. Это опровергает правило «любой QUIC защищён от ТСПУ».
- [VPN Guild / RKS Global, январь 2025](https://files.rks.global/vpn-block-report_01.25.pdf):
  сообщает о блокировках OpenVPN, WireGuard и IKEv2/IPSec. Это историческое
  свидетельство; оно не доказывает одинаковую работу правил на каждом операторе.
- [Операционные наблюдения Shadowsocks/VMess, апрель 2024](https://github.com/net4people/bbs/issues/363):
  сообщают о фильтрации по характеру вложенного TLS. Это сообщения исследователей
  и пользователей, а не общенациональный эксперимент.
- [Наблюдения массовых блокировок IP, сентябрь 2026](https://github.com/net4people/bbs/issues/671):
  затронуты серверы REALITY и AmneziaWG. Блокировка адреса не равна распознаванию
  протокола; в режиме разрешительного списка обычная маскировка также недостаточна.
- [OpenVPN fingerprinting](https://www.usenix.org/conference/usenixsecurity22/presentation/xue-diwen)
  и [вложенный TLS](https://www.usenix.org/conference/usenixsecurity24/presentation/xue-fingerprinting):
  общие исследования механизмов распознавания. Сами по себе они не являются
  измерением конкретного российского оператора.

## Все сетевые семейства этой сборки

«В ограничении» — доступность при включённом «Только протоколы с маскировкой».
С выключенным ограничением прежняя поддержка профилей сохраняется.

| Семейство | Оценка и ограничения | В ограничении |
|---|---|---|
| AnyTLS | TLS, разбиение и padding против вложенного TLS; нет достаточных независимых измерений по РФ. Не гарантия устойчивости. | TCP, проверка сертификата, Chrome uTLS |
| NaiveProxy | Chromium HTTP/2/3 и padding, сопротивление активным пробам при правильном сервере; IP/SNI остаются фактором. | HTTP/2; HTTP/3 только с разрешением UDP |
| Hysteria 2 | QUIC/HTTP/3; SNI может фильтроваться. Salamander/Gecko требуют совпадающего серверного пароля; не помогают при полном запрете UDP. | Только с разрешением UDP, проверка TLS, Chrome QUIC imitation |
| TUIC | QUIC/TLS; шифрование и производительность не означают маскировку. Нет основания объявлять невидимым ТСПУ. | Только с разрешением UDP, проверка TLS, без 0-RTT |
| Hysteria 1 | Старое отдельное семейство; не считать равным Hysteria 2. UDP и параметры сервера определяют доступность. | Исключён |
| VLESS | Обычный VLESS не обеспечивает маскировку. REALITY + Vision, TLS/WS/gRPC и XHTTP — разные конфигурации; нельзя утверждать блокировку всех по одному названию. Есть сообщения об IP/TCP ограничениях. | Исключён по запросу пользователя |
| VMess | Есть наблюдения фильтрации вложенного TLS; транспорт меняет признаки, но название само не гарантирует маскировку. | Исключён |
| Shadowsocks | Есть наблюдения фильтрации. AEAD/2022 защищает содержимое, но не устраняет анализ размеров/поведения. | Исключён |
| Trojan | TLS-обёртка; вложенный TLS, серверная маскировка и TLS fingerprint требуют отдельной оценки. Нет достаточных измерений для безусловного допуска. | Исключён |
| ShadowTLS | Версия и корректная цепочка с внутренним протоколом принципиальны; нельзя классифицировать один узел без всей цепочки. | Исключён вместе с непроверяемыми цепочками |
| WireGuard / wireguard_legacy | Известные признаки handshake; блокировки описаны. | Исключён |
| WARP | WireGuard-подобный транспорт и известная инфраструктура; настройки шума не гарантируют обхода. | Узлы исключены, включённая цепочка выдаёт ошибку |
| AmneziaWG (awg) | Маскировка зависит от версии и согласованных параметров. JSON этого ядра не содержит HeaderProtectionKey и других параметров AWG 3.x, поэтому нельзя обещать поддержку последнего AWG 3.1. UDP/IP блокировки остаются. | Исключён до полной проверки версии/параметров |
| OpenVPN client/server | Блокировки и fingerprinting подтверждены; TCP/443 сам по себе не превращает OpenVPN в HTTPS. | Исключён |
| OpenConnect | TLS/DTLS VPN; нет достаточного основания считать устойчивым к российскому DPI. | Исключён |
| Snell | Собственные версии/обфускация; нет достаточных независимых данных по РФ. | Исключён |
| Mieru | Собственный TCP/UDP транспорт; публичного подтверждения универсальной устойчивости в РФ нет. | Исключён |
| TrustTunnel | HTTP/2/3 туннелирование; отдельная реализация, не эквивалент NaiveProxy. Недостаточно российских измерений. | Исключён |
| SSH | SSH handshake различим; шифрование не маскирует его под HTTPS. | Исключён |
| SOCKS / HTTP CONNECT | Обычный SOCKS/HTTP не скрывает протокол; HTTPS CONNECT зависит от TLS и серверного поведения. | Исключены |
| Tor | Зависит от мостов/транспортов и доступности узлов; Tor не отдельный гарантированно доступный протокол. | Исключён |
| Psiphon | Набор динамических транспортов; внешний тип не даёт проверяемой гарантии конкретного транспорта. | Исключён |
| DNSTT | DNS-туннель, зависит от резолверов и домена; маленькая пропускная способность и ограничения DNS. Не обычный быстрый VPN. | Исключён |
| GooseRelay | Специализированный relay; доступность инфраструктуры важнее названия. Недостаточно независимых измерений. | Исключён |
| Xray nested config | Контейнер разных протоколов, включая XHTTP; необходим разбор внутренней конфигурации, чтобы оценивать маскировку. | Исключён как непрозрачный контейнер |
| MASQUE endpoint | Зарегистрирован клиент/серверный endpoint; HTTP/3/UDP/IP ограничения актуальны. Не доказанная защита от ТСПУ. | Исключён |
| tunnel_client/server | Туннельные endpoints; не категория подтверждённой защиты от DPI. | Исключены |

`ShadowsocksR` удалён upstream и представлен ошибкой, а старый `wireguard`
outbound заменён endpoint. `MASQUE outbound`, `Tailscale`, `Tailcat` и
`Cloudflared` требуют тегов, отсутствующих в Makefile этой сборки. Они не должны
выдаваться за работающие доступные протоколы. `direct`, `bridge`, `block`,
`hinvalid`, группы выбора, TUN и DNS-транспорты — служебные компоненты.
IKEv2/IPSec/L2TP не представлены самостоятельными клиентами этой сборки.

## Реализованная политика

1. Опциональное ограничение находится в «Скрытие VPN» и выключено по умолчанию.
   По умолчанию внутри ограничения разрешены только AnyTLS и Naive TCP.
2. Отдельный переключатель UDP/QUIC, тоже выключенный по умолчанию, добавляет
   Hysteria 2, TUIC и Naive HTTP/3. Он не обещает обход блокировки UDP.
3. Обязательны TLS и проверка сертификата. Не допускаются отключённый SNI,
   явно старый TLS и непроверяемые detour/REALITY-обёртки этих типов.
   AnyTLS использует Chrome uTLS; Naive свой Chromium без дополнительного
   небезопасного concurrency; TUIC без 0-RTT.
4. Пароли, адреса и серверная обфускация не изменяются. Подписка не может
   переопределить политику устройства; native Always-on применяет её тоже.
5. При отсутствии совместимых серверов — понятная ошибка конфигурации, без
   бесконечного автопереподключения и возврата к исключённым протоколам.
6. Прямые исключения маршрутизации управляются отдельно. Это ограничение выбора
   VPN-серверов, а не переключатель полного туннеля.

Схема допуска — консервативное продуктовое решение, не измеренный рейтинг
«лучших протоколов». Реальную доступность проверяет сеть пользователя.
Адаптивный режим повышает устойчивость к потерям/задержкам, но не снимает
блокировку IP и не превращает старый сервер в сервер нового протокола.
