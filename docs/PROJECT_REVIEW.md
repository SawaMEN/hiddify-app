# Проверка реализации и сборки — 4 октября 2026

Проверена ветка main, исходный коммит a6832803. Исправления внесены
последовательными коммитами в fix/staged-stability, PR #12.

## Архитектура и фактическая область сборки

Flutter/Dart отвечает за интерфейс, профили и настройки. Android Kotlin
запускает VPN/Proxy service; взаимодействие с hiddify-core идёт через локальный
gRPC и Flutter Method/Event Channels. Конфиги и сведения о профилях хранятся
в файлах и Drift. В этой версии репозитория присутствует Android ARM64 build;
каталогов сборки iOS, Windows, Linux и macOS нет. Их сборка этим PR не проверяется.

## Исправленные проблемы

- dynamic_color 2.x использует несовместимые с текущими Material imports типы.
  Учтено исправление PR #11: совместимая ветка 1.9.x. Сохранены актуальные
  Flutter 3.47.5, Dart 3.13.4, Riverpod, protobuf, gRPC и Android toolchain.
- Окно разрешения VPN переводит Activity в inactive/paused. Закрытие клиента
  ядра в этот момент прерывало подключение. Inactive больше не закрывает ядро;
  pause во время перехода соединения также сохраняет его. Resume повторяет setup
  только если foreground действительно закрывался. Setup и close сериализованы.
- Цикл ожидания Started выходил только из switch, а не из цикла. Теперь он
  завершается сразу; новые события ожидаются без повторного чтения старого Starting.
- Повторный setup оставлял gRPC-каналы и подписки. Старые каналы закрываются,
  probe Hello получает deadline и освобождается в finally; LastStream обрабатывает
  ошибки/закрытие источника и завершает ожидающие futures.
- Ошибки changeOptions игнорировались, а недоступность foreground ошибочно
  трактовалась как отсутствие background. Теперь ошибки доходят до UI, проверяется
  ответ background, snapshot обновляется после успешного применения.
- Future подключения не ожидался вызывающим кодом. Защита SingleCall теперь
  используется с await, сохраняя результат и освобождение после ошибки.
- При remote/offline обновлении профиля finally исполнялся до запуска ленивого
  TaskEither. Очистка теперь выполняется после завершения операции.
- Ошибка вложенной подписки молча удаляла её строки, отмена могла сохранять
  неполный результат; временные файлы вложенных загрузок оставались на диске.
  Теперь ошибка прерывает обновление, отмена проверяется до записи, файлы удаляются.
- Некорректные subscription-userinfo поля вызывали исключение при разборе.
  Неизвестные, пустые, отрицательные и некорректные значения пропускаются;
  отсутствие total/expire сохраняет трактовку безлимита, срок ограничен диапазоном DateTime.
- Запуск из плитки передавал пустой путь в Mobile.start. Используется сохранённый
  путь; второй аргумент оставлен пустым, поскольку API принимает configContent,
  а не имя профиля (проверено по upstream platform/mobile/mobile.go).
- Notification polling использовал blocking gRPC внутри coroutine и удалял
  foreground notification при отмене/ошибке опроса. Используется suspend execute;
  отмена опроса сохраняет уведомление, scope освобождается при уничтожении службы.
- Публикация логов передавала изменяемый буфер. Слушатели получают отдельный
  неизменяемый snapshot. Загрузка core теперь проверяет HTTP status и завершение
  скачивания перед распаковкой.

## Зависимости

Проверены все прямые hosted зависимости и dev_dependencies по pub.dev API.
На момент проверки версии в pubspec.lock совпадают с последними стабильными
версиями, кроме dynamic_color: 2.1.0 намеренно не применяется до миграции
Material API. Последний опубликованный стабильный hiddify-core — v4.1.0,
он уже указан в dependencies.properties. Dev-сборка по существующей схеме
использует upstream draft, production — версию из dependencies.properties.

## Верификация

Автономная проверка `dart tool/check_async_runtime.dart` покрывает
ожидание/кэширование событий, таймаут, ошибку и завершение потока, однократное
освобождение, конкурирующие старты, освобождение после исключения и malformed
subscription metadata. Она добавлена в оба Android CI workflow.

Полный CI выполняет pub get, генерацию переводов и Dart-кода, анализатор
и release APK для ARM64. Результат конкретного коммита следует смотреть
в checks PR #12; статус последующего коммита не подтверждается результатом предыдущего.

Проверка реального подключения требует Android-устройства и воспроизводимого
профиля. Нужно проверить первый запуск с разрешением VPN, отказ/повтор разрешения,
возврат в приложение, повторное подключение и смену профиля, плитку, выключение
экрана, подписку с вложенными URL и отмену её обновления. Эти сценарии на устройстве
в данной среде не выполнялись.
